FINAL JAVA VERIFICATION — 10 OCTOBER 2026

The first source reconstruction was not functionally identical to the Java inside
the original executable. This review found and corrected real decompiler defects.
The final source and rebuilt binaries in this package include those corrections.

What changed

17 methods contained arithmetic grouping or lost-temporary defects:
- DoubleNumeric.floor: restored the negative-number rounding expression. The
  former reconstruction could return -1.25 for floor(-1.25); the original returns -2.
- InstantStopModule.choose: preserved the previous minimum before overwriting it,
  so the original stopping-direction decision is retained.
- BridgeAssistModule.State.footprintAir and CriticalsModule.onEvent: restored
  original calculation grouping.
- TargetCombatStatus.boxDistance/squared, TimingAccess.squared,
  PlacementGeometry.squared, RenderMath.distanceSquared/model/row/project,
  RotationMath.distance, CanvasPath.roundCap,
  RecoveredGui.Layout.next, RecoveredGuiScreen.buildFramePlan and
  TrajectoryPrediction.charge: restored original floating-point operation order.

Two additional methods were brought closer to the original: RenderAccess.execute
now evaluates rendering receivers and arguments in the original order, and
CoreModules.sourceOnlyIntervals uses the original Module[] component type.
Twelve default constructors regained their original strict floating-point flag.

Fresh-build checks also found and fixed build-script defects: wildcard dependency
paths inside compiler argument files, missing manifests after namespace remapping,
and the absent dependency-preparation/toolchain-detection steps described by the
previous README. A fresh full Java/native build now passes its artifact checks.

as data. Their hashes matched the earlier extraction. Original EXE SHA-256:

For EACH of the three naming variants:

What this establishes, and what it does not

The check found material errors that the earlier compilation/signature/startup
checks missed, and the corrected expressions/decision were checked against the
original instructions after recompilation. No additional normal-use mismatch was
identified by the completed static review.

This is thorough static reconstruction verification, not a universal mathematical
proof that every possible execution is identical. Some compiler-generated
details, reflective metadata, malformed-input behavior and concurrent external
mutation remain outside that claim. In particular, InnerClasses metadata differs
in 40 classes and 48 methods gain MethodParameters metadata. Generated helper
names, synthetic markers and generic signatures also differ. Classfiles and JARs
are not byte-identical. Debug data, stack frames and reflection-visible details
are not part of the instruction-flow equivalence claim.

Neither the original specimen nor the corrected launcher/DLL/payloads were
executed during this review. The retained Lunar startup/menu logs describe the
earlier build and do not constitute a runtime test of these corrected binaries.
