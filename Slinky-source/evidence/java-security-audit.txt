Independent static Java security audit of extracted payload-101.jar, payload-102.jar and payload-103.jar

No target executable, DLL, class or JAR was executed. Python scripts treated ZIP members/class constant pools as data; CFR output was inspected as text.

Scope and coverage:
- Each JAR has exactly the same set of 509 class entry names (1,527 class files total). Constant-pool parsing found no malformed/unknown tags and covered 41,371 / 41,792 / 41,442 UTF8 constants respectively. Evidence: work/jar-audit-constants.json, generated by work/jar_audit.py.
- CFR summary files for all three report only a structuring failure in the shaded ASM SignatureReader.parseType utility. Relevant application sources were successfully decompiled, with unavailable Minecraft dependency type warnings expected because the game itself was not supplied.
- Non-class entries: 48 in 101, 49 in each mapped variant; these totals include directory entries. Resources are fonts/licenses, JSON game/UI/initial-settings metadata, icon pixel coverage data, manifest, and mapping text in mapped variants. No DLL/EXE/additional JAR was found inside these archives. Resource inventory: work/jar-resource-audit.json.

Verdict limited to this Java layer:
The code inspected implements injected Minecraft client modifications. I found no Java credential/token stealing, external C2 connection, downloader, shell invocation, scheduled task/startup persistence, or remote payload retrieval path. This is a bounded static finding, not proof that the enclosing native EXE/DLL is safe. NativeBridge calls need the separate native analysis.

Recovered* classes and those metadata fields are strong static evidence this sample is a semantic reconstruction build, not a provenance guarantee about a vendor release.

Limits:
This audit covers the embedded Java archives and their local resources. JNI native bridge is intentionally allowed to modify the game's bytecode, so the enclosing launcher/native payload requires its own assessment. The absence of ordinary Java exfiltration APIs does not establish a universal negative about dynamically composed behavior or native code. No behavioral execution/testing was performed, in accordance with user instruction.
